# 📻 Sonara Radio v2.6.1

**Sonara Radio** — веб-плеер для прослушивания радиостанций со всего мира. Приложение сначала обращается к [Radio Browser API](https://www.radio-browser.info/), а при его недоступности использует ежедневно обновляемый статический каталог. Работает как Progressive Web App (PWA).

## ✨ Ключевые фишки и особенности

### 🚀 Архитектура и Производительность
- **PWA:** Полный вариант содержит manifest и Service Worker, который сохраняет интерфейс после успешной загрузки. Установка зависит от браузера и ОС и требует HTTPS или localhost. Кеш может ускорить повторный запуск; первый запуск требует загрузки файлов.
- **Встроенные стили:** Tailwind CSS скомпилирован заранее и включён в HTML. Компилятор Tailwind в браузере не запускается.
- **HLS (.m3u8):** Локальная `hls.js` (v1.5.17) используется в поддерживаемых браузерах; при недоступности этой библиотеки полный вариант пробует CDN. В отдельном HTML библиотека встроена. В остальных случаях поток передаётся HTML Audio, и воспроизведение зависит от поддержки формата браузером. Для загрузки HLS через библиотеку сервер должен разрешать соответствующие запросы. Шрифты и иконки загружаются с CDN: без сети шрифт заменяется системным, иконки могут отсутствовать.
- **Источники каталога:** Radio Browser API остаётся основным источником. Пока идёт запрос, показывается сохранённая база. При отказе API используется кеш каталога; если кеша нет, загружается `data/stations.json`, который GitHub Actions ежедневно обновляет в ветке `catalog`. Последний резерв — встроенная подборка. База старше шести часов обновляется с GitHub в фоне.
- **Рейтинги в резервном каталоге:** Workflow запланирован раз в день и запрашивает до 1000 станций по голосам и до 1000 по кликам для `data/rankings.json`. Данные соединяются по UUID; интерфейс показывает дату снимка. Клики Radio Browser не измеряют длительность прослушивания. Для станций вне выборок рейтинг неизвестен и обозначается «—». При ошибке обновления сохраняется предыдущий снимок с его исходной датой.
- **Избранное без API:** Избранные станции сохраняются отдельно с названиями и прямыми адресами потоков; ограничение кеша истории в 200 станций на них не влияет. Старые записи переносятся из кеша и дополняются при доступном API или каталоге.

### 🎨 Интерфейс и UX
- **Светлая и тёмная темы:** Переключатель в шапке меняет оформление всего интерфейса и сохраняет выбор в браузере.
- **Анимации переходов:** View Transitions используется, если API доступен. Иначе интерфейс обновляется без этой анимации.
- **SVG-заглушки:** Отсутствующий или не загрузившийся логотип заменяется иконкой с первой буквой названия станции.
- **Оформление:** CSS-размытие фона, цветные акценты и моноширинное отображение битрейта, если он известен. Кодек и битрейт берутся из данных станции, а не измеряются плеером.
- **Индикатор воспроизведения:** Декоративные CSS-полоски движутся при событии `playing` и останавливаются при буферизации, паузе, завершении и ошибке. Индикатор не анализирует звук и не показывает частотный спектр; дополнительных запросов к потоку не выполняет.

### 🎛 Функционал плеера
- **Поиск:** Параллельные запросы по названию (до 60 результатов) и тегу (до 40), с объединением по UUID. Устаревшие ответы не применяются после смены раздела. Это ограниченная выборка, а не просмотр всех совпадений.
- **Фильтры:** Страна и минимальный битрейт фильтруют уже загруженные станции. Неизвестный битрейт не проходит положительный порог. Онлайн-раздел популярного получает до 100 станций; раздел жанров — до 16 на каждый из восьми выбранных жанров. «Показать ещё» раскрывает загруженные записи и не запрашивает следующую страницу API.
- **История и свои потоки:** Сохраняются 20 последних станций, для которых был запрошен запуск; успешное звучание не проверяется. Можно добавить название и адрес собственного HTTP/HTTPS-потока в избранное. Воспроизведение зависит от формата и доступности сервера. Клики пользовательских станций не отправляются в Radio Browser.
- **Переподключение:** Для каждого адреса — один запуск и две повторные попытки с паузами 1,5 и 3 секунды. Ожидание старта ограничено 12 секундами, буферизации после начала воспроизведения — 15 секундами. После исчерпания попыток плеер пробует следующий адрес той же станции. Стабильное воспроизведение в течение 30 секунд восстанавливает бюджет повторных попыток для текущего адреса; короткие запуски этого не делают. Успешное восстановление не гарантируется.
- **Запасные адреса:** До шести HTTP/HTTPS-ссылок на станцию: основной адрес и пять запасных. Их можно указать при добавлении своей станции либо изменить кнопкой «Адреса потоков» в карточке или плеере. Это локальная настройка, каталог Radio Browser не изменяется. Сохранение адресов текущей играющей станции переподключает её. Поиск запасных потоков по названию станции не выполняется.
- **Следующая с отсчётом:** После отказа всех адресов появляются «Повторить», «Следующая (10)» и «Отменить переход». Через 10 секунд выбирается следующая ещё не отказавшая станция из текущего списка. Переход прекращается после пяти отказов подряд или когда непроверенных станций больше нет. Повтор, остановка, ручной выбор станции и редактирование её адресов отменяют ожидающий переход. Если браузер запретил запуск без действия пользователя, автоматического перехода нет. Выполнение отсчёта зависит от работы страницы: в приостановленной вкладке переход может задержаться.
- **Мобильное управление:** До ширины 1023 px — компактный нижний плеер, кнопки управления не меньше 44×44 px (пуск 56×56), навигация «Каталог / Избранное / Поиск / Меню» и настройки под «Ещё». Меню и фильтры не занимают первый экран. Высота плеера учитывается в отступе списка; формы прокручиваются, добавлены безопасные отступы экрана. Предыдущая и следующая станции выбираются по текущему загруженному списку с переходом по кругу.
- **Media Session:** При поддержке браузером передаются метаданные и обработчики Play/Pause/Next/Prev/Stop. Появление кнопок и обложки в системном интерфейсе зависит от браузера и ОС.
- **Таймер сна и выключение Windows:** Таймер останавливает плеер, пока страница выполняется. Закрытие браузера или сон устройства прерывают его работу. Выключение требует установленного помощника Windows, подтверждения в браузере и подтверждения в системном окне. Системное окно ждёт ответа до 25 секунд; после ОК команда планирует выключение через 30 секунд. Отмена запланированного выключения — `shutdown /a`. При положительном таймауте Windows подразумевает принудительное закрытие приложений даже без явного `/f`: перед подтверждением сохраните работу. Это поведение описано в [документации Microsoft](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/shutdown). Предусмотрен деинсталлятор; разрешение запуска внешнего протокола зависит от браузера.
- **Резервная копия:** JSON v3 содержит избранные UUID, доступные названия, основные и запасные адреса станций, свои потоки и настройки адресов для избранных и своих станций. Принимаются v2, v1 и старые массивы UUID; неподходящие записи отбрасываются. Старые UUID без восстановленного адреса не становятся автономными после одного экспорта. Каталог, история, тема и таймер в резервную копию не входят.

## 🛠 Технический стек

- **Frontend:** HTML5, Vanilla JavaScript (ES2022)
- **Стилизация:** Tailwind CSS (скомпилированный)
- **Иконки:** FontAwesome; основные кнопки плеера используют встроенные SVG и системные символы
- **Медиа:** HTML5 Audio API, HLS.js (локальный вендор `vendor/hls.min.js`)
- **Каталог:** [Radio Browser API](https://de1.api.radio-browser.info/) с резервным `data/stations.json` из ежедневного [экспорта Radio Browser](https://backups.radio-browser.info/).

## 🚀 Установка и Использование

Sonara Radio не требует собственного сервера. Избранное хранится в localStorage, полный каталог — в IndexedDB браузера.

Ежедневная выгрузка запускается workflow `Update radio catalog`; его можно запустить вручную через Actions → Run workflow. Рабочий снимок хранится в отдельной ветке `catalog`, поэтому ежедневные обновления не раздувают историю `main`. При ошибке скачивания или неполном экспорте прежний снимок остаётся доступен. Если API не отвечает, браузер пробует GitHub Raw, затем jsDelivr и локальный снимок из полного ZIP. Полный каталог и рейтинги сохраняются в IndexedDB: при следующем запуске база показывается сразу, пока проверяется API. База старше шести часов обновляется в фоне. При отказе хранилища приложение продолжает работать с сетевыми источниками и встроенной подборкой. Кеш относится к браузеру и адресу приложения; перенос избранного между браузерами выполняется экспортом и импортом JSON. Станции, для которых в старой копии был только UUID, требуют хотя бы одного успешного запроса для восстановления адреса. Доступность самих аудиопотоков зависит от их владельцев и сети пользователя.

1. **Для локального запуска** распакуйте полный ZIP и откройте `index.html` либо скачайте отдельный `sonara-radio.html`. Запуск через `file://` проверен в Chrome; доступность хранилища и сетевых запросов зависит от браузера. Встроенный файл `data/stations.json` из ZIP при таком запуске не читается: для него нужен HTTP-сервер.
   В релизе есть отдельный `sonara-radio.html`: это вариант в одном файле со встроенными `sonara-core.js`, HLS и установщиком выключения ПК. Для установки PWA используйте полный ZIP.
   Собрать такой файл из исходников можно командой `node scripts/build-standalone.js sonara-radio.html`.
2. **Для установки как PWA (на рабочий стол/экран телефона):** браузеры требуют безопасный контекст (HTTPS или `localhost`). Обычный запуск через `file://` для PWA не подойдёт. Запустите любой локальный HTTP-сервер, например:
   - `npx http-server` (в папке проекта)
   - Расширение Live Server в VSCode
   - `python -m http.server`
   После этого откройте локальный адрес. Если браузер поддерживает установку PWA, используйте его меню установки.
3. **Для активации функции "Выключить ПК" (Windows):**
   - Запустите `install-shutdown.bat` от имени пользователя (он создаст обработчик протокола с подтверждением в `%LOCALAPPDATA%\SonaraRadio`).
   - Для деинсталляции и очистки реестра запустите `uninstall-shutdown.bat`.

## 🧪 Тестирование и CI

В репозитории настроен автоматический тестовый набор и GitHub Actions CI:

```bash
npm ci
node tests/run-tests.js
```

Тесты запускают общий `js/sonara-core.js` и основной скрипт приложения в Node VM. Они проверяют валидацию хранилища, backup v3, v2, v1 и legacy, перенос автономного избранного, сохранение и обновление каталога в IndexedDB, добавление и восстановление своей станции, ограниченные переподключения и запасные адреса, отсчёт и отмену автоперехода, восстановление HLS, индикатор воспроизведения, Media Session, работу загрузчиков и поздний ответ Explore. Проверки Service Worker и скриптов выключения здесь статические; реальное выключение компьютера не выполняется. Проверка в Chrome дополняет автоматические тесты, но не подтверждает совместимость со всеми браузерами, устройствами и потоками. В v2.6.0 обе сборки проверены в Chrome с эмуляцией касаний на 320×568, 360×640, 390×844, 430×932, 667×375, 844×390, 768×1024, 1024×768 и 1280×800, в обеих темах. Проверены навигация, переключение станций, раскрытие настроек, поиск, кнопки ошибки и доступ к последней карточке. Физические iPhone и Android не проверялись. Результаты аудита описаний функций — в [docs/feature-audit.md](docs/feature-audit.md).
