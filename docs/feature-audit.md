# Проверка описаний функций — 2026-10-02

Проверены README, надписи интерфейса, HTML/JS, Service Worker, manifest, сборщик отдельного HTML, экспорт каталога, workflow, скрипты выключения и описания восьми опубликованных релизов от v2.2 до v2.4.0. Проверка касается соответствия заявлений реализации; это не полный аудит безопасности или всех радиопотоков.

| Заявление или функция | Что подтверждено и что исправлено |
|---|---|
| «Аппаратная анимация спектра, 100% станций, без задержек» | CSS повторяет заранее заданное движение пяти полосок и не получает аудиоданные. Название заменено на индикатор воспроизведения. Убраны гарантии аппаратного ускорения, охвата и задержек. |
| Синхронизация индикатора | Исправлены остановка при `waiting`, `ended`, `emptied`, отказе `play()` и окончательной ошибке HLS. При восстановлении HLS анимация ждёт нового `playing`. Переключение станции останавливает прежнюю анимацию. `stalled` сам по себе означает остановку поступления данных и не доказывает прекращение звучания из буфера, поэтому остановка индикатора привязана к `waiting`. |
| CORS | Индикатор не анализирует звук и не создаёт дополнительных запросов. Это не снимает сетевые ограничения с HLS и аудиопотоков. |
| «Все потоки стабильны», «90% блокировалось» в v2.2 | Статистики для этих утверждений нет. В описании старого релиза они заменены на факт удаления Web Audio и оговорку зависимости от сервера, формата и браузера. |
| «Нативный HLS» | В поддерживаемых браузерах используется hls.js. Локальное наличие библиотеки не делает поток автономным и не снимает требования к доступу на сервер. |
| «Мгновенный запуск PWA», установка во всех ОС | Есть manifest и кеш интерфейса. Установка и скорость зависят от браузера, ОС, сети и состояния кеша; универсальные обещания удалены. |
| «Всё приложение одним index.html» | Источники полного проекта включают JS и vendor. Отдельный sonara-radio.html в новых релизах содержит эти зависимости, но обращается по сети к станциям; шрифты и иконки остаются внешними. |
| Открытие ZIP через file:// | Прямое открытие HTML проверяется в Chrome. Вложенный data/stations.json этим способом не загружается; для него нужен HTTP. PWA через file:// не регистрируется. |
| «Zero runtime cost», «аппаратные переходы» | Компилятор Tailwind не выполняется в браузере. CSS всё равно обрабатывается браузером. View Transitions включается только при поддержке API; аппаратное ускорение не гарантируется. |
| Логотипы и внешние иконки | SVG используется при отсутствии или ошибке логотипа. Исправлен сброс флага ошибки логотипа при смене станции. При отказе CDN FontAwesome иконки могут отсутствовать. |
| Кодек и битрейт | Плеер отображает данные источника, а не измеряет поток. Неизвестный кодек больше не подменяется MP3; новые пользовательские станции не получают придуманный битрейт 128 kbps. Старые сохранённые значения не переопределяются, поскольку могли быть заданы пользователем. |
| «Все станции по жанрам», поиск | Восемь жанров, до 16 записей каждый; поиск до 60 по названию и 40 по тегу; отдельный жанр до 80. Надписи исправлены. «Показать ещё» раскрывает загруженные записи, а не следующую страницу API. |
| Фильтры | Применяются к загруженной выборке. Поиск всех станций страны по API не реализован. Неизвестный битрейт не проходит положительный порог фильтра. |
| «По прослушиваниям» | Используется clickcount Radio Browser. Подпись заменена на клики; количество и длительность фактических прослушиваний не измеряются. |
| История | До 20 UUID выбранных для запуска станций. Успешное звучание не подтверждается; описание исправлено. |
| Свои станции | Кнопки ссылались на отсутствовавшие openCustomModal, closeCustomModal, saveCustomStation. Функции восстановлены; проверяются название и HTTP/HTTPS URL, запись появляется в избранном и резервной копии. |
| Media Session | Передаются метаданные и действия при поддержке API. Исправлены Play/Pause: повторный Play не останавливает поток, повторная Pause не запускает его. Поддержка на всех ОС не заявляется. |
| Таймер и «безопасное автоматическое выключение» | Таймер зависит от выполнения страницы. Помощник Windows ждёт системного подтверждения 25 секунд, после ОК планирует выключение через 30 секунд; браузер запрашивает отдельное подтверждение. Вызов протокола не является гарантией безопасности, а при `/t` больше нуля Windows подразумевает `/f` даже без явного флага. В подтверждениях добавлено пояснение о закрытии приложений и сохранении работы. Реальное выключение при проверке не выполнялось. |
| Резервная копия | Включает избранное с доступными адресами и свои станции. Не включает каталог, историю, тему, таймер. Старые UUID без адресов требуют восстановления; неправильные записи отбрасываются, а не превращаются в рабочие станции. |
| Кеш каталога | Сохранение зависит от разрешения и места в IndexedDB. Избранное зависит от localStorage. Отказ хранилища не позволяет обещать сохранение между запусками. |
| Ежедневный каталог и рейтинги | Есть расписание Actions, но успешное обновление каждый день не гарантируется. Дата каталога — время формирования JSON, а не проверка доступности всех станций. При ошибке workflow прежняя опубликованная версия остаётся. |
| MIT и совместимость | Код проекта имеет MIT License; это не гарантия доступности станций или разрешение на их контент. Версии браузеров и ОС вне проведённых проверок не объявлены проверенными. |

Исторические архивы релизов не перезаписываются. Исправления старых описаний помечаются как уточнения, а рабочие исправления распространяются в v2.4.1.

Разница между ожиданием данных и остановкой поступления данных сверена с [MDN: waiting](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/waiting_event) и [MDN: stalled](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/stalled_event). Требования HLS сверены с [документацией hls.js](https://github.com/video-dev/hls.js#cors), поведение выключения — с [Microsoft: shutdown](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/shutdown).

## Дополнение v2.5.0

Восстановление потока теперь ограничено двумя повторами для каждого из максимум шести адресов. После исчерпания адресов запускается отменяемый отсчёт 10 секунд до следующей станции; цепочка ограничена пятью отказами. Запрет браузера на запуск требует действия пользователя. Конечное аудио завершается без переподключения. Эти сценарии проверены автоматически и в Chrome на имитированных отказах и тестовом аудио; доступность всех радиостанций не заявляется.
